# 用 dsh_run 把任务委派给 DeepSeek Harness

DSH（DeepSeek Harness）是本机另一个独立、能力完整的编码智能体：它有自己的模型、技能库、插件与 MCP 工具。
通过 MCP 服务器 `deepseek-harness` 暴露的 `dsh_run` 工具，你可以把一整件事交给它：它会在你指定的工作目录里
自己读文件、改代码、跑命令，最后把**最终答复**交回来。

## 什么时候用

- 用户明确要求交给 DSH / DeepSeek Harness 做。
- 任务需要很多步、跨多个文件，或预计要跑很久（大重构、批量改写、全仓调研、长时间验证）。
- 任务要用到 DSH 侧才有的能力（它的技能库、它挂载的 MCP 服务器、它的插件生态）。
- 想要"第二意见"：让 DSH 独立实现或独立复核，再和你的结论对照。

## 什么时候别用

- 一两步就能完成的小改动——直接自己做更快。
- 需要与用户反复确认的交互式工作：`dsh_run` 是一次性任务，跑完就退出。
- 用户没有授权的工作目录：DSH 会用自身权限真的改文件、跑命令。

## 怎么调

```json
{
  "task": "自包含的完整任务说明：目标、约束、验收标准、要动的文件/目录",
  "cwd": "绝对路径；强烈建议显式传用户当前工作区",
  "session_id": "可选，沿用上次返回的 DSH 会话，继续同一段工作",
  "timeout_ms": 900000,
  "include_trace": false
}
```

要点：

1. **任务说明必须自包含**。DSH 看不到这段对话，别写"按上面的方案改"，把背景、目标、验收标准、
   禁止事项写全。
2. **总是显式传 `cwd`**，用用户当前工作区的绝对路径。服务端会优先用 MCP roots，但显式传最保险；
   省略时它退回 MCP 服务进程的目录（可能是 `~/.copilot`）。
3. **同一件事接着做，就把上次结果里的 `会话=session-xxx` 通过 `session_id` 传回去**；
   沿用要求工作目录一致，换了 cwd 的会话不能沿用。
4. **超时要给够**。默认 15 分钟；大任务显式给 `timeout_ms`（上限 60 分钟）。超时后用更大的超时
   配合 `session_id` 继续。
5. **返回的是 DSH 自己的最终答复**，不是逐条工具日志。需要审计它做了什么时加 `include_trace: true`。
6. **排查接入问题**用 `dsh_info`：CLI 路径、版本、DSH_HOME、可用档案、默认工作目录一次看全。
7. 把 DSH 的结论如实转述给用户，别当成自己亲自验证过的结果；有疑问就自己复核一遍。
